## Findings (severity, evidence, reproduction, required regression)
1. **HIGH, source-proven inconsistent DPI/zoom state; native manifestation NOT RUN.** Editor.hpp 354–461 overrides checkSizeConstraint/onSize without updating private SDK calcZoomFactor. Pinned vst3editor.cpp 2185/2211/2240: base open initializes cache, base constraint updates it, inherited setContentScaleFactor restores it after changing content scale. Thus after opening 100%, resizing to 125%, then changing monitor DPI, cached 100% can replace saved 125%. Test real IPlugViewContentScaleSupport at 100→150→100 with user zoom 125%, expected absolute 187.5% at 150% DPI (1800×1080); verify native HWND, hit testing, preferences, host rejection. Existing 100/150 lifecycle from default zoom and custom resize tests separately do not detect interaction. Correct one zoom authority, not appearance.
2. **HIGH, source-proven incomplete live UI recall/synchronization; native manifestation NOT RUN.** Vst3.cpp 248–255 writes ui.zoom/help only. Editor initializes zoom at construction, HelpButton retains separate enabled flag; existing editor neither resizes nor synchronizes button on setState. Hover reads shared preference. Two open editors on one controller can disagree. Reproduce valid controller setState while attached (1.25/help true), compare actual geometry, indicator and hover, then second attached view, invalid payload and reopen. Current fresh-controller tests do not exercise live recall or simultaneous views.
3. **MEDIUM, source finding/host-dependent persistence risk.** UI-only zoom/help changes do not notify optional IComponentHandler2::setDirty(true) as defined by Steinberg for nonparameter changes. Host may not mark project modified. Native fake host and actual Studio Pro project dirty/save/reopen after *only* UI changes required. Not a claim of observed DAW data loss.
4. **LOW/MEDIUM, executed FAIL: malformed numeric text accepted.** ValueEntry.hpp entryNumber strips '+' before from_chars, so '+-25' succeeds for Curve and writes .375; '-25' correctly succeeds and '25oops' correctly rejects. Violates strict invalid-input preservation. Add parser and native CTextEdit negative: no controller/processor state or host edit notification changes, PCM unchanged.
5. **LOW, executed FAIL: extreme unrepresentable sample rate.** Core::prepare accepts DBL_MAX (finite positive), dx underflows/denominator overflows, after 100 ticks progress remains 0; ordinary 48000 positive control advances and modulates. No normal DAW rate failure established. Reject unusable rates safely before altering state. Test setup rollback at valid rate and native malformed setup; check bounds without breaking documented supported rates.
6. **MEDIUM, source finding: inactive bus handling.** Processor::render Vst3.cpp 148–176 ignores bus activation and considers only channel count/pointers. SDK requires processing activated buses only; inactive sample pointers may be null, not necessarily null. Challenge deactivated input/output with valid nonnull sentinel buffers, no stale input read/output writes. Existing generic IO activation roundtrip is not a PCM sentinel oracle. Native manifestation NOT RUN.
7. **RELEASE BLOCKER, package fact:** no SDK/VSTGUI notices in exact 15-file ZIP. SDK MIT requires copyright/permission notice, VSTGUI redistribution condition requires notice/conditions/disclaimer in accompanying documentation/materials. Include exact pinned licenses in actual distribution, validate final archive. No separately supplied accompanying notice verified. Also clean Windows installation/runtime DLL availability NOT RUN.
8. **LOW/MEDIUM, risk hypotheses NOT RUN:** preview MID labels at 1%/99% can overlap START/END; 4096 dense pulses at max length/rate cannot all resolve at 858-pixel plot width. Native pixel oracle exercises selected moderate settings, not these extremes. Test actual pixels and GUI work under rapid automation at max density; avoid changing approved layout unless necessary. Fixed 4/4 reference and no playhead intentional, not a failure. Also text editing under simultaneous host automation/focus loss, rejected host resize, GUI resources missing/corrupt remain untested interactions.
9. **QA policy gap, not demonstrated audio fault:** malformed later queue points retain previously applied valid prefix; native process can return false after writing valid prefix. This matches documented Lane reject-remainder policy, not automatically an atomicity bug. Mock queue test: continuous two points, discrete offset, invalid first point, NaN behave as expected; duplicate second point init accepted, bad flag true, prefix .25 retained. Define and test actual Windows host failure/rollback semantics; do not claim full malformed-queue robustness.
